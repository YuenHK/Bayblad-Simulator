# STEAM 陀螺模擬器網頁設計規格

- 日期：2026-08-28
- 狀態：待用戶審閱
- 目標裝置：iPad、Mac 及一般桌面電腦
- 主要語言：繁體中文
- 課程依據：`STEAM陀螺_S1_Maker課程大綱_v4.pdf`

## 1. 產品目標

建立一個可經互聯網公開存取的 STEAM 陀螺模擬器，讓學生在實物製作前：

1. 使用預設參數化形狀設計三層陀螺；
2. 即時查看俯視、分解及 3D 成品預覽；
3. 檢查設計是否符合課程規格；
4. 查看重量、質量分布及相對性能預測；
5. 透過房間、大廳、節拍發射及即時物理模擬進行線上對戰；
6. 把設計和對戰紀錄保存至教師後台，供教師統計及匯出。

系統只呈現數據、模擬結果和賽果。學生端不提供最佳化分析、改良建議或排行榜，讓學生自行分析設計取捨。

## 2. 第一版範圍

### 包含

- 三層參數化陀螺設計器
- 規格即時檢查
- 俯視、分解及 3D 預覽
- 相對性能預測
- 公開房間大廳
- 兩個對戰席及不限人數觀賽區
- 每輪節拍發射判定
- 伺服器主導的輕量 2D 物理對戰
- 對戰分、挑戰分及總分
- iClass MDM 身份整合接口
- Cookie 快取身份及訪客模式
- 教師後台、統計、Excel 匯出、手動刪除及備份

### 不包含

- 自由繪畫輪廓
- 完整 3D 剛體物理
- 離線對戰
- 學生排行榜
- 學生端參數分析或自動改良建議
- 對實物表現作精確或保證性預測

## 3. 課程規格及裝配規則

設計器按目前 v4 課程大綱採用以下規格：

- 結構：3 層
- 最大直徑：60 mm
- 最大高度：40 mm
- 每層厚度：6 mm
- 最大重量：60 g
- 邊緣：必須圓角，不能有尖角、刀口或幼頸
- 安全：不可分體，不可有鬆動配件

用戶已指定金屬圓形貼片的額外規則：

- 金屬貼片只可位於最底層亞加力膠下方；
- 貼片置中並由中央軸心夾持；
- 金屬貼片不設螺絲孔；
- 第一版每枚陀螺最多使用一塊金屬圓形貼片；
- 學生可選擇不使用貼片，或選擇一個預設直徑；
- 貼片直徑不可超出最底層在相同半徑位置的輪廓範圍。

## 4. 學生身份識別

### 4.1 主要方式

學生由 iClass MDM 派發的專屬 Web Clip 進入平台。Web Clip 網址包含不可讀的簽署裝置代碼。伺服器驗證代碼後，透過 iClass API 或由學校提供的對照資料取得：

- 裝置名稱
- 學生姓名
- 班別
- 學號

學生毋須輸入任何身份資料。

### 4.2 開發前驗證項目

必須向 iClass 確認至少支援以下其中一項：

- 按裝置派發個別化 Web Clip URL；或
- 提供伺服器端 API，以裝置代碼查詢裝置名稱、學生及班別；或
- 提供等效的學校 SSO／受管理身份整合方式。

這是外部整合依賴，不影響訪客模式及其他功能開發。

### 4.3 Cookie 備援

首次成功識別後，伺服器建立不含個人資料含義的隨機裝置憑證，並以 `Secure`、`HttpOnly`、`SameSite` Cookie 保存。日後 iClass 暫時無法連接時，伺服器可用該憑證恢復上一次已驗證身份，教師後台標示為「Cookie 快取」。

### 4.4 未識別訪客

完全無法識別時仍可使用所有設計及線上對戰功能。系統分配例如 `訪客-4F8A` 的隨機顯示名稱，並記錄匿名裝置代碼。普通網頁不嘗試讀取 iPad 裝置名稱或 MAC 位址。

伺服器可保存連線 IP 作排查用途，但 IP 不視為學生身份。若 iClass API 日後提供 MAC 或管理裝置識別碼，可作輔助欄位保存。

## 5. 陀螺設計工具

### 5.1 每層參數

學生為上層、中層和底層分別設定：

- 預設形狀：圓形、圓角正多邊形、圓角星形、波浪形
- 邊數／角數
- 直徑或面積
- 圓角程度
- 旋轉角度
- 顏色

形狀參數的可用範圍由系統配置限定，不能生成尖角、刀口或幼頸。

### 5.2 共用裝配參數

螺絲孔屬三層共用裝配參數，不容許每層使用互不相同的孔位。學生設定：

- 螺絲孔數量
- 排列半徑
- 整體旋轉角度

系統把相同孔位套用到三層，並檢查孔位不會超出任何一層輪廓、不會與中央軸孔相撞，亦不會形成過薄結構。

### 5.3 層次及金屬貼片

- 學生以拖放方式調整上、中、底三層次序；
- 每層原有形狀及參數會隨層次移動；
- 底部金屬貼片提供「沒有」及多個預設直徑；
- 金屬貼片保持置中，不提供偏心或單邊放置。

### 5.4 即時預覽及計算

設計畫面同步顯示：

- 當前層俯視圖
- 三層疊合俯視圖
- 分解圖
- 可旋轉及縮放的 3D 成品
- 底部金屬貼片及中央軸心關係

系統即時計算：

- 各層及總面積
- 亞加力膠和金屬貼片估算重量
- 重心偏移
- 轉動慣量
- 質量分布
- 轉速、旋轉時間、穩定及耐撞的相對評分

相對評分只供方案比較，介面須清楚標示為「模擬預測」，不能描述為實物測試結果。

### 5.5 規格檢查

違規時，相關欄位及模型位置即時標紅並提供具體原因。學生可以保存未完成或違規草稿，但只有全部通過的設計才能放入對戰席及按下「準備好」。

伺服器會在進入對戰前重新驗證全部參數，防止修改前端資料繞過限制。

## 6. 大廳及房間

### 6.1 大廳

公開大廳列出所有房間：

- 房間名稱
- 房間碼
- 等待中／對戰中狀態
- 兩個對戰席玩家名稱
- 觀賽人數

大廳不顯示排行榜或累積分數。任何人可由房間列表或房間碼進入。

### 6.2 房間結構

每個房間包含：

- 對戰玩家 1 席
- 對戰玩家 2 席
- 不設產品人數上限的觀賽區

系統仍可設連線速率、訊息頻率及總連線保護，避免惡意流量拖慢服務，但不在介面顯示固定觀賽人數上限。

房間顯示兩名對戰玩家名稱、準備狀態、觀賽人數及觀賽玩家名稱。

### 6.3 房主

- 建立房間者成為房主；
- 房主可移到觀賽區並保留房主身份；
- 房主可關閉房間及把對戰玩家移到觀賽區；
- 對戰開始至整場完成期間，房主不能移動對戰玩家或關閉單一對戰；只有教師後台可因管理或安全需要強制中止；
- 房主不可刪除比賽紀錄；
- 房主斷線後保留身份兩分鐘；
- 逾時未重連，房主身份轉移給在房間停留最久的使用者；
- 全房人數變成零後保留兩分鐘，期間有人重返便取消關閉，否則自動刪除房間。

### 6.4 席位及準備

- 房主或其他使用者可自由由觀賽區補入空置對戰席；
- 兩個對戰席都選定合規陀螺並按下「準備好」才開始；
- 開始後鎖定席位和設計，不能中途換人或修改參數；
- 完成整場後才解鎖席位。

## 7. 發射節拍判定

三局兩勝的每一輪都重新進行一次發射判定。雙方接收同一個由伺服器排程的倒數及節拍時點；裝置計算按鍵與目標時點的差距，再由伺服器檢查合理性。

判定分為：

- `Perfect`
- `Great`
- `Good`
- `Miss`

即使 `Miss` 亦可低速發射，不會直接判負。初始建議倍率為：

| 判定 | 初始角速度倍率 | 初始移動／碰撞力度倍率 |
|---|---:|---:|
| Perfect | 1.10 | 1.10 |
| Great | 1.00 | 1.00 |
| Good | 0.90 | 0.90 |
| Miss | 0.75 | 0.75 |

倍率存放於伺服器配置，可在實測校準後調整，不由學生端控制。

對戰玩家只看見自己的判定，不看見對方判定；觀賽者可看見雙方判定。

## 8. 輕量 2D 物理對戰

### 8.1 模型定位

採用俯視 2D 剛體碰撞和參數模型，不模擬完整三維傾斜、軸尖彈跳或材料破壞。輸入包括：

- 外輪廓及碰撞半徑
- 總重量
- 重心偏移
- 轉動慣量
- 質量分布
- 摩擦及旋轉衰減
- 穩定及耐撞相對值
- 發射角速度及移動力度倍率

### 8.2 權威計算及重播

- 對戰結果由伺服器統一計算；
- 客戶端只傳送設計、準備和節拍輸入，不自行決定賽果；
- 每輪保存隨機種子、模型版本及輸入參數；
- 教師可用相同種子重播相同結果；
- 小量有界隨機變化令同類設計不會每次產生完全相同過程，但不能蓋過主要設計差異。

## 9. 對戰流程及計分

每場最多三輪，先勝兩輪者勝出。

每輪流程：

1. 同步倒數；
2. 雙方完成節拍判定；
3. 伺服器執行對戰；
4. 公布該輪勝方，但不顯示累積對戰分；
5. 未分出整場勝負時進入下一輪。

每輪判定：

- 對手先停止旋轉：勝方 1 對戰分
- 對手被撞出指定安全圈：勝方 1 對戰分
- 自己未接觸對手便飛出場：對手 1 對戰分
- 雙方同時停止或同時出界：重賽
- 模擬結構失效事件：該輪判負；正式學生設計正常情況下應由規格驗證避免此事件

整場完成後才顯示：

- 每輪勝負
- 雙方對戰分
- 重量差
- 挑戰分
- 該場總分

挑戰分只給較輕一方：

`挑戰分 = min(重量差（g）× 0.05, 0.5)`

`總分 = 對戰分 + 挑戰分`

學生端不顯示排行榜。賽後雙方可選擇再戰、留在對戰席或移到觀賽區。

## 10. 觀賽同步

- 觀賽者接收房間狀態、雙方陀螺、戰況及雙方發射判定；
- 觀賽者不能發送控制對戰的指令；
- 中途加入者接收當前房間快照，不重播之前的整段動畫；
- 即時訊息採用節流及合併更新，避免大量觀賽者令伺服器重複計算物理；
- 伺服器只計算一次對戰，再把同一狀態廣播給所有觀賽者。

## 11. 教師後台

### 11.1 登入

- 帳號：`admin`
- 初始及持續可用密碼：`fwft2026`
- 不強制更改密碼
- 學生網站及教師後台均可由互聯網公開存取

安全控制仍必須包括：

- HTTPS
- 密碼只以安全雜湊保存，不在前端或資料庫明文出現
- 登入失敗限速、逐步延遲及暫時鎖定
- `Secure`、`HttpOnly`、`SameSite` 工作階段 Cookie
- CSRF 防護
- 閒置自動登出
- 登入成功、失敗、IP 及後台操作稽核紀錄

### 11.2 即時管理

教師可：

- 查看所有房間、對戰席、觀賽者及準備狀態
- 查看正在進行的對戰
- 暫停全平台對戰
- 強制關閉房間
- 把使用者移出房間

### 11.3 對戰紀錄

每場保存：

- 日期及時間
- 身份狀態：iClass 即時／Cookie 快取／未識別
- 能取得時的學生姓名、班別、學號及裝置名稱
- 訪客代碼及匿名裝置代碼
- IP、瀏覽器及大概裝置類型
- 房間、兩名玩家及觀賽人數
- 雙方完整陀螺參數
- 每輪發射判定
- 物理模型版本及隨機種子
- 每輪結果、對戰分、挑戰分及總分

### 11.4 統計

提供：

- 每日、每週、每月活躍裝置數
- 設計次數、建立房間數及完成對戰場數
- 形狀、邊數、尺寸、重量、螺絲孔、層次排序及金屬貼片直徑的使用比例
- 各參數組合的平均分、勝率及樣本數
- 高分組與低分組的參數差異
- 分開顯示設計參數、發射判定及對手強弱的關係

教師分析使用「目前最高平均表現參數」名稱，不宣稱為絕對最佳設計。結果必須同時顯示樣本數、資料日期、篩選範圍及模型版本。只有達到系統配置的最低樣本門檻才列入高低表現比較；預設門檻為 10 場完成對戰。

### 11.5 Excel 匯出

匯出的 `.xlsx` 包含獨立工作表：

- 對戰紀錄
- 逐輪結果
- 陀螺參數
- 身份及裝置狀態
- 使用量統計
- 參數分析

匯出檔須保留篩選所用日期範圍和產生時間。

## 12. 資料保留、刪除及備份

- 系統不自動刪除個人、裝置、設計、房間或對戰資料；
- 資料保存至管理員主動刪除或平台停止使用；
- 管理員可按學生、班別、日期或整批選取資料；
- 刪除前可先匯出 Excel；
- 刪除操作要求再次輸入管理員密碼及二次確認；
- 稽核紀錄保留刪除人、時間和範圍，但不保留已刪學生內容；
- 系統提供加密的定期資料庫備份及還原程序；備份採滾動保留，已刪除的個人資料須在備份週期屆滿後一併消失，不能由一般後台搜尋或匯出；
- 校方負責確認長期保存學生個人資料的目的、告知安排及政策符合要求。

## 14. 斷線及錯誤處理

- 玩家或房主斷線後保留席位／身份兩分鐘；
- 重連後恢復房間位置及伺服器的當前狀態；
- 無法恢復時轉到大廳並顯示清楚原因；
- iClass 失敗時依次嘗試 Cookie 快取及訪客模式；
- 物理模擬或計分失敗時該輪不計分並安全重賽；
- 重複提交準備或節拍輸入必須具冪等性，不能開始兩場或重複計分；
- 學生介面只顯示可理解的繁體中文訊息，不顯示堆疊或內部錯誤碼；
- 伺服器保存可供管理員追查的錯誤識別碼及技術紀錄。

## 16. 驗收及測試

### 16.1 設計及規格

- 每種預設形狀及其參數範圍均能生成閉合、安全輪廓；
- 面積、重量、重心及慣量計算有單元測試；
- 三層孔位保持一致；
- 金屬貼片只在底部置中出現；
- 邊界值 60 mm、40 mm、6 mm、60 g 的通過／拒絕行為一致；
- 前端和伺服器驗證結果相同。

### 16.2 即時對戰

- 兩名玩家及多名觀賽者看到一致戰況；
- 玩家看不到對方節拍判定，觀賽者看得到雙方；
- 相同輸入和種子能重播相同賽果；
- 三局兩勝、重賽、對戰分及挑戰分計算正確；
- 中途斷線、兩分鐘重連、房主轉移及空房關閉均有自動測試；
- 重複網絡訊息不會造成雙重開賽或雙重計分。

### 16.3 身份及安全

- iClass 即時、Cookie 快取和訪客三種狀態均能對戰；
- 個人資料不出現在 URL、前端原始碼或非 HttpOnly Cookie；
- 管理員密碼不以明文保存；
- 登入限速、工作階段到期、CSRF 及權限測試通過；
- 訪客舊紀錄可在日後成功識別時安全連結，不誤合併其他裝置。

### 16.4 教師後台

- 對戰紀錄欄位完整；
- 日／週／月統計能以已知測試資料重算；
- 參數分析顯示樣本數及篩選範圍；
- Excel 可正常開啟，所有工作表及欄位完整；
- 刪除需重新驗證並留下不含已刪內容的稽核紀錄；
- 備份能在獨立測試環境成功還原。

### 16.5 裝置及可用性

- 實機測試至少涵蓋一部學校管理的 iPad、Safari、Mac Safari 及桌面 Chrome／Edge；
- iPad 觸控按鈕、節拍輸入、3D 操作及橫直向版面可用；
- 在校內一般 Wi-Fi 延遲和短暫斷線下仍可恢復房間；
- 教師後台在真實資料量下保持可搜尋、篩選及匯出。
