# 對戰判定、老師確認流程及自適應 UI 設計

日期：2026-08-31

## 目標

本次修改包含三個互相獨立但可一併交付的改良：

1. 消除學生在發射判定期限後看到 `ROUND_CLOSED` 的紅色錯誤，同時維持伺服器判定的權威性。
2. 老師登入後，不再為永久刪除紀錄重新輸入密碼或 `DELETE`，改用兩階段明確確認。
3. 讓學生端及老師端在電腦、iPad 和手機上自動採用合適版面，並保留現有字體、字級、字型和配色。

## 範圍與不變條件

- 無痕模式可正常設計、加入房間及對戰。
- 所有無痕視窗關閉後，瀏覽器會清除訪客憑證；下次建立新訪客身份。網站不以 IP、MAC 位址或裝置指紋強行拼接身份。
- 已完成的無痕訪客對戰仍永久保留在老師後台原有身份紀錄中。
- 發射判定仍以伺服器收件時間為準；過期發射不得改寫已產生的 `Miss`。
- 老師端仍保留登入工作階段逾時、登出、CSRF 防護和不可修改的操作稽核紀錄。
- 不修改現有可見字體、字級、字型或配色。

## 1. 發射判定期限與錯誤處理

### 現況與根因

伺服器在判定目標時間後的接受期限結束時，會把尚未發射的玩家判為 `Miss` 並關閉該輪。學生端目前沒有在相同期限停用發射按鈕，因此仍可向已關閉回合送出新的 `launch.tap`，伺服器便回覆 `ROUND_CLOSED`。無痕模式只影響身份和瀏覽器儲存，不會主動關閉回合。

### 協議與資料流

- `launch.schedule` 明確攜帶伺服器接受截止時間。
- 客戶端沿用現有時鐘同步，把伺服器截止時間轉換成客戶端顯示時間。
- 截止時間到達後，節拍元件停止接受觸控、滑鼠及 Space 鍵輸入，按鈕停用並顯示「本輪已結束，等待下一輪」。
- 若截止前產生的指令因網絡延遲在回合關閉後抵達，伺服器把該參與者已存在的最終判定視為權威結果，不回傳需要學生處理的紅色 `ROUND_CLOSED` 錯誤。
- 過期指令不可建立第二個結果、不可改寫 `Miss`、不可重新開始模擬，亦不可影響其他玩家。

### 錯誤顯示

- 真正的協議不一致、身份錯誤或無有效回合仍顯示錯誤。
- 單純因截止時間與網絡延遲造成的已完成回合，學生端只顯示等待下一輪狀態。

## 2. 老師端兩階段確認

### 操作流程

1. 老師選擇刪除範圍並建立刪除預覽。
2. 第一個畫面顯示範圍、學生身份數、設計數及對戰數；老師按「繼續」。
3. 第二個畫面再次顯示「此操作不可還原」及相同摘要；老師按「確定永久刪除」。
4. 伺服器核對登入工作階段、CSRF、預覽憑證、篩選雜湊及預覽有效期後執行。

### 安全規則

- 不再要求重新輸入密碼或輸入 `DELETE`。
- 第二個確認按鈕不與第一個「繼續」按鈕置於相同位置，降低連續誤按風險。
- 預覽過期、篩選範圍改變、工作階段失效或請求重放時，必須重新建立預覽。
- 後台稽核繼續記錄執行者、範圍、結果、日期時間及請求診斷資料；不記錄密碼。

## 3. 方案 A：斷點自適應 UI

### 裝置規則

- 電腦（寬度至少 1024px）：設計預覽與控制台並排，結果保持在可見區域；大廳、老師房間和統計使用多欄版面。
- iPad（600–1023px）：橫向在空間足夠時使用雙欄，直向自動改為單欄；按鈕、圖表及表格不得超出可視區域。
- 手機（最多 599px）：設計室使用「控制台／模擬預覽／預測結果」三個頁籤，每次只顯示一個面板。

### 手機對戰專注模式

- 玩家進入發射判定時隱藏主要導覽列。
- 畫面優先顯示房間辨識、倒數、節拍線和大型發射按鈕。
- 本輪進入模擬或整場對戰結束後恢復導覽列。
- 觀賽者不顯示發射按鈕，仍可觀看兩位玩家的判定結果。

### 通用響應式規則

- 房間席位、觀眾名單、老師房間卡片、篩選器及圖表在窄畫面改為單欄。
- 寬表格置於可橫向捲動容器；主要操作不依賴水平捲動才能觸及。
- 支援 iPad 和手機直橫向切換，以及瀏海與主畫面指示器安全區。
- 觸控目標保持現有至少 44px 的可操作尺寸。
- 沿用 `prefers-reduced-motion`；減少動態效果時不使用會引起不適的位移動畫。
- 頁籤具備正確的 `tablist`、`tab`、`tabpanel` 語意，可用鍵盤操作，切換時保留尚未提交的設計資料。

## 元件邊界

- `LaunchCoordinator`：管理伺服器接受期限、判定及已關閉回合的權威結果。
- 即時協議：傳送發射目標與截止時間，維持嚴格資料驗證。
- `RealtimeClient`：轉換伺服器時間、處理已完成回合的非致命結果及保留真正錯誤。
- `RhythmLaunch`：顯示倒數、接受單次輸入、在截止後鎖定並呈現等待狀態。
- 老師刪除 API：以有效工作階段、CSRF 及一次性預覽資料授權刪除，不再使用密碼再驗證欄位。
- `DeleteDialog`：負責預覽與第二階段確認，不保存或傳送密碼。
- 設計室響應式外殼：桌面／iPad 重排現有面板，手機提供三頁籤；各設計子元件維持單一職責。
- 對戰頁外殼：根據裝置闊度、玩家角色及對戰階段切換專注模式。

## 測試與驗收

### 發射判定

- 先建立能重現「回合自動結束後再按發射會得到 `ROUND_CLOSED`」的失敗測試。
- 驗證截止後觸控、點擊及 Space 均不再送出新指令。
- 驗證延遲到達的指令不顯示紅色錯誤，亦不改寫 `Miss` 或產生第二次模擬。
- 驗證準時的兩名玩家仍可各提交一次，觀眾仍只在雙方完成後看到兩方判定。

### 老師端

- 驗證刪除流程不呈現密碼和 `DELETE` 欄位。
- 驗證未完成第二次確認不能刪除。
- 驗證預覽憑證、篩選雜湊、CSRF、有效工作階段及稽核紀錄仍受保護。

### 自適應 UI

- 在 390px 手機、768px iPad 直向、1024px iPad 橫向及 1440px 電腦視窗測試學生端和老師端。
- 驗證手機三頁籤、資料保留、鍵盤操作和對戰專注模式。
- 驗證各寬度沒有非預期頁面水平捲動、遮擋或不可觸及操作。
- 驗證直橫向切換、瀏海安全區及減少動態效果。

## 交付條件

- 相關單元、元件及整合測試全部通過。
- 學生端和老師端完成指定視窗尺寸的瀏覽器視覺檢查。
- 生產環境以兩個獨立訪客完成建立房間、準備、發射、至少一輪判定及結果流程，不出現 `ROUND_CLOSED` 紅色錯誤。
- 老師端在生產環境完成一次不涉及真實資料的安全測試流程，確認兩階段確認及工作階段保護正常。
