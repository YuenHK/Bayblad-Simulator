# 學生端線上遊戲化介面設計

## 目標

把學生端改造成新潮的線上陀螺競技遊戲介面，在不改動設計規則、房間權限、伺服器判定、三局兩勝計分及老師端資料格式的前提下，提高設計、發射及對戰的臨場感。美術採混合風格：設計室與大廳使用清晰的科幻電競 HUD，發射判定及對戰才加入高強度街機式演出。

## 範圍與邊界

- 只改學生端輸出；老師登入、統計、紀錄、排行榜及 Excel 匯出保持原狀。
- 保留控制台、模擬預覽、預測結果三個頁籤及所有現有表單標籤，避免破壞課堂流程與自動測試。
- 不改伺服器節拍判定及力量計算。客戶端只根據伺服器排程和回傳判定播放效果。
- 學生端不新增分析或設計建議。
- 不使用第三方遊戲圖像、音樂或音效；聲音以 Web Audio 即時合成。

## 視覺系統

- 深藍黑背景配合青藍、紫色及橙紅能量色，使用 CSS 變數集中管理。
- 面板採深色半透明 HUD、細緻網格、能量邊線和柔和光暈；文字維持高對比。
- 頂部狀態列顯示平台、身份、連線狀態、音效開關及動態效果開關。
- 互動元件在按下時立即縮放或發光；動畫只使用 `transform`、`opacity` 或低成本 SVG/CSS 屬性。
- 重要狀態使用文字、圖示與顏色三重表達，不以顏色作唯一訊息。

## 設計室

- 控制台呈現為裝備配置模組；原有數值、形狀、螺絲及金屬貼片控制不變。
- 模擬預覽成為全息展示台，加入平台能量環、掃描光及柔和倒影，但不遮擋陀螺輪廓。
- 預測結果使用能力值儀表顯示速度、持久、穩定及抗撞；原有數字保留。
- 不合規參數使用 HUD 警告呈現；「用此設計參戰」成為主要能量啟動按鈕。

## 大廳與房間

- 房間卡改為競技配對卡，仍顯示房間碼、兩名玩家、觀眾數及狀態。
- 兩個玩家席採左右對戰構圖，中間以 `VS` 能量標誌分隔；準備後座位亮起並顯示鎖定效果。
- 房主轉往觀賽區、觀眾補位、準備及自動關房規則完全保留。
- 觀眾名單為可捲動面板，不遮擋主要操作。

## 發射判定

- 水平能量跑道包含接近區、準確區及完美區；移動標記沿用伺服器目標時間。
- 倒數時以能量脈衝及節拍音提供預備訊號；按下發射同一畫面幀觸發按壓、衝擊環及合成音效。
- 判定顯示 `PERFECT｜完美`、`GREAT｜準確`、`GOOD｜偏差`、`MISS｜失誤` 的大型回饋；實際協議值按既有 `LaunchGrade` 映射，不創造新判定結果。
- 玩家只看自己的判定；觀眾同時看到雙方判定。
- 聲音尚未解鎖、網絡延遲或時間同步期間仍可正常完成操作。

## 對戰競技場

- SVG 競技場加入同心能量環、透視網格、場邊燈帶及柔和霧光。
- 陀螺保持學生原有顏色與輪廓，加入速度相關的旋轉殘影、外圈光及光帶。
- 客戶端以相鄰戰況幀的距離、速度及場邊位置推算純視覺事件：輕碰、高速碰撞和場邊摩擦。
- 視覺事件必須由 `sequence` 產生穩定識別，避免 React 重繪重複播放火花或聲音。
- 輕碰播放短火花及金屬音；高速碰撞增加方向性火花、衝擊環及極短震動；場邊摩擦使用紅橙火花。
- 回合只顯示本輪勝方；總分仍只在整場結束後顯示。

## 音效、效能與可存取性

- `GameAudioController` 在首次可信任互動後建立 AudioContext，提供節拍、發射、判定、碰撞、回合及勝負合成聲。
- 音效預設開啟但在瀏覽器允許前保持靜默；固定音效開關並以安全本機儲存記住選擇。
- 粒子品質按裝置能力與畫面尺寸分為完整及精簡兩級，不依賴個人資料。
- 動態效果開關與 `prefers-reduced-motion` 共同決定低動態模式；低動態模式移除震屏、掃描、殘影及大量粒子，保留文字與顏色回饋。
- 不使用高速全屏閃爍；亮度變化保持局部和短暫。
- 所有主要觸控目標至少 44px，保留鍵盤、焦點、ARIA live region 及螢幕閱讀器文字。

## 響應式行為

- 桌面使用寬幅 HUD，可同時顯示控制、預覽及能力面板。
- iPad 橫向採雙欄；對戰場置中，玩家資料位於兩側或上方。
- iPad 直向及手機保留三頁籤；發射階段隱藏非必要導覽並使用全螢幕專注模式。
- 支援安全區、畫面旋轉及較大文字，不以固定高度截斷內容。

## 測試與驗收

1. 單元測試覆蓋音效偏好、判定映射、碰撞事件去重、粒子品質及低動態模式。
2. 元件測試確認玩家私密判定、觀眾雙方判定、音效開關及回合／總分顯示規則。
3. 學生 build、typecheck、現有完整 web 測試全部通過。
4. 公開站在 Chrome、獨立瀏覽器 context、Firefox、iPad WebKit 及手機尺寸完成設計、房間、發射、對戰及賽果流程。
5. 老師端登入、統計、排行榜和 Excel 匯出回歸測試通過。
6. 正常模式及減少動態模式均不產生未捕捉錯誤、持續音效或失控動畫。
